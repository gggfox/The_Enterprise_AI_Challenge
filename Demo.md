# Tiendita — Talk to your data

## The challenge

Build a "talk to your data" interface where a non-technical user asks a business question in plain Spanish or English and gets back a chart, a number, and a one-sentence insight — no SQL required.

The reference example was a hospital where users asked about operating-room costs. Their trick for keeping the LLM grounded was to first force a narrowing question ("which operating room?") and pre-extract a small table for that scope before the conversational turns started. That worked for them, but it made the conversation feel like a form.

## Our take

We swapped the hospital domain for a fictional Mexican convenience-store chain called **Tiendita** (think OXXO / 7-Eleven). The user is a regional manager. They ask things like *"how were sales in CDMX last week?"* or *"and what about MTY?"* — the same way they would ask a junior analyst.

We deliberately do **not** force a narrowing question up front. A regional manager's day jumps between stores and regions; making them name a scope before they can speak makes the assistant feel like a kiosk. We keep the conversation open and prune context implicitly as it flows.

## How a turn works

1. The user clicks **Start**. The browser opens a WebSocket directly to Deepgram's Voice Agent and streams microphone audio (linear16 PCM at 16 kHz). The Voice Agent does STT + LLM + TTS in one pipe.
2. The LLM has one tool registered: `query_sales(scope?, days?)`. Both arguments are optional. When the user asks something the LLM can't answer from memory, it emits a `FunctionCallRequest`.
3. Our frontend hands the call to Convex — specifically the `analytics.querySales` query, which aggregates the precomputed `rollup_daily_store_sales` table for the requested scope and window.
4. The result (totals + a daily series) goes back to the Voice Agent as a `FunctionCallResponse`. The LLM narrates a one-sentence insight in TTS; the same JSON drives the on-screen chart and headline number.

> **Why this is fast:** every analytical question hits a precomputed rollup table (one row per `(store, date)`), not the raw transactions. Convex indexes them by `(storeId, dateKey)` so a 30-day chain-wide query is a handful of small index scans.

## Why context-pruning still matters (and how we do it)

Even with rollups, you don't want to dump all of last year's data into the LLM's context every turn. The hospital example pruned by forcing a scope choice. We prune by tracking what the user has been talking about and reusing it silently.

Concretely, the frontend keeps a `focus` state — the last successful `{ scope, days }` pair the agent queried. Every system-prompt rebuild includes a line like:

```
Current focus: scope="region:CDMX", days=30
```

…so the LLM stays oriented. Follow-up questions are encouraged to omit arguments:

| User says | Focus after the turn |
| --- | --- |
| "How were sales in CDMX last week?" | `region:CDMX`, `7d` |
| "And the past month?" | `region:CDMX`, `30d` |
| "What about MTY?" | `region:MTY`, `30d` |
| "And just CDMX-POL?" | `store:CDMX-POL`, `30d` |

The user gets natural conversation; the model gets a narrow data window. No PDF middle layer, no forced narrowing question.

## Voice agent details

- **Provider:** Deepgram Voice Agent V1 (`wss://agent.deepgram.com/v1/agent/converse`).
- **STT:** Deepgram `nova-3`.
- **LLM:** OpenAI `gpt-4o-mini` (configured in the `Settings` message).
- **TTS:** Deepgram `aura-2-thalia-en`. Linear16 at 24 kHz, played through a chained `AudioBufferSource` pipeline so chunks don't gap.
- **Barge-in:** when Deepgram emits `UserStartedSpeaking`, we cancel any in-flight TTS so the agent doesn't talk over the user.
- **Auth caveat:** the Deepgram API key is browser-exposed via `VITE_DEEPGRAM_API_KEY` for the demo. Before any real deploy this should be replaced with a short-lived scoped key minted by the Bridge.

## Data model

Synthetic 18-month dataset for 10 stores across CDMX, MTY, and GDL. Generated by `packages/convex/scripts/generate-fixtures.ts` and seeded into Convex via `seedRetail.run`.

| Layer | Tables |
| --- | --- |
| **Raw** | `stores`, `products`, `categories`, `customers`, `transactions`, `transaction_items`, `inventory_movements`, `promotions` |
| **Rollups** | `rollup_daily_store_sales`, `rollup_daily_store_category_sales`, `rollup_hourly_store_sales` (heatmap), `rollup_product_monthly`, `rollup_services_monthly`, `rollup_geo_monthly` |

Every analytical question the voice agent serves hits a rollup; raw tables are reserved for drill-downs we haven't built yet.

## What's wired today

- `/ask` route in the FE with a Start/Stop button, live conversation transcript, focus pill, and result card (headline number + daily bar chart + one-sentence insight from the agent).
- One Convex analytics module: `listStores`, `listRegions`, `latestDate`, `querySales`.
- One tool: `query_sales(scope?, days?)` with implicit focus binding.

## What's next (rough order)

- **Spanish.** The hook already accepts `language: 'es' | 'multi'` — we just need to swap the TTS voice (`aura-2-celeste-es`) and translate the system prompt.
- **Bridge-minted short-lived Deepgram keys** instead of `VITE_DEEPGRAM_API_KEY`.
- **More tools:** category breakdowns, hourly heatmaps, product movers.
- **Optional Redis briefing layer:** pre-warm a small JSON digest in front of `query_sales` so the LLM can answer *"what's down this week?"* type questions without a tool round-trip on every turn.

## Try it

```bash
# 1. Push the Convex schema + analytics module (needs Node 22+)
pnpm -F @enterprise-ai/convex dev

# 2. Seed the synthetic 18-month dataset (needs SEED_SECRET set)
pnpm -F @enterprise-ai/convex seed-retail

# 3. Run the FE
pnpm -F @enterprise-ai/web dev
```

Then open <http://localhost:3000/ask>, sign in with Clerk, click **Start**, grant mic access, and ask:

> "How were sales in CDMX last week?"

Follow up with a question that omits the scope or window and watch the focus pill update.
